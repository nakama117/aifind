# 日文评测准备

`evaluation/candidates.jsonl` 与同名 CSV 提供 100 个真实来源页面的标题和链接，固定为 70 条 calibration、30 条 holdout。采集日期 2026-10-04。只保存最小引用信息，不分发来源全文。所有 `human`、`resultReview` 为空；**这是待标注候选库，不是人工金标或已通过评测的结果**。

候选覆盖 12 个来源，70 条英文与 30 条日本来源（Sakana 页面可能有英日版本）。由人工检查实际语言、重要性、营销噪声、重复事件、英日对照关系；不足的类别需在任何调参开始前替换补齐并重新冻结划分。同一事件的不同语言、转载、续报应放在同一划分，避免把 holdout 信息泄漏到校准集。目前按来源语言分层、URL 哈希划分，**尚未由人工完成事件隔离审核**。

1. 打开 CSV，逐条阅读原文，记录选/不选、内容类型、事件组、营销标记、来源关系，以及标注者和日期。不要让模型替代人类金标。
2. 经许可的原文保存在私有 `.data/evaluation/`，不要提交或公开全文。按照 `scripts/eval-selection.ts` 的 `GoldRow` 结构制作 gold.jsonl，`bodyOriginal` 放原文；`bodyZh` 为旧字段名，本站可放日文，但初期建议保留原文输入。使用 `samplingContext.benchmarkSplit` 区分 calibration 与 holdout。
3. 只使用 70 条校准集调整提示词和门槛，记录模型名、提示词版本、样本文件 SHA-256 和成本。遵守五维加权、噪声压制和安全边界，不凭感觉改分数。
4. 冻结版本后，30 条 holdout 仅跑一次独立验收。评估全过程使用单独测试/评测数据库，配置项目密钥及安全阀；所有付费调用仍通过请求回执和预算检查。
5. 上游 `eval-selection.ts` 验证的是筛选评分，不包含日文写作和事件归并全流程。另通过受限 worker 处理评测输入，保存输出、双次评分回执、生成摘要、事件 ID，人工逐条对照。不要把筛选准确率当作日文质量合格率。
6. 30 条中至少 27 条日文可直接使用；关键事实编造和明显错误归并必须为 0。记录每一条的判定、错误说明与复核人；任一关键错误则修正后以新独立样本复验。

可从 JSONL 的空字段补充如下记录（不要事先填“通过”）：

```json
{
  "human": {"reviewer":"人工填写", "reviewedAt":"ISO时间", "decision":"select或reject或either", "eventGroup":"人工事件ID", "marketing":false},
  "resultReview": {"reviewer":"独立复核人", "outputFile":"私有输出文件", "outputSha256":"散列", "japaneseUsable":true, "criticalFactError":false, "wrongMerge":false}
}
```

正式上线记录必须引用人工签核文件和真实运行日志。目前所有验收项均为待完成。本地预览的 8 篇官方文章摘要未经过生产模型的完整流程，不得当作这 100 条评测的人工金标或独立验收结果。

2026-10-04 后续完整候选版已经通过真实模型流水线生成146篇日文资讯，并对每篇最终版本进行AI事实复核，10篇曾有编辑修正。原始模型判定139篇 supported，其余7篇另有代理对照来源的异议处理记录；原始判定未覆盖。这仍不是人工评测，不填写上述100条候选的人工字段，也不声称达到27/30标准。详见 [完整交付记录](verification-launch-20261004.md) 和私密内容包的复核记录。
