# 内容管理与 SEO 操作手册

后台为中文，公开内容为日文。无需修改数据库即可完成日常改稿、精选调整、撤稿与恢复。

## 登录

本机入口：<http://127.0.0.1:3100/admin/login>。正式部署后沿用 `/admin/login`。

使用本机私密 `.env` 中的 `ADMIN_PASSWORD`，没有单独用户名。密码已配置，不要将 `.env` 或其中的任何密钥发到聊天或上传公开仓库。换服务器时运行 `node scripts/init-env.ts` 生成新凭据；修改密码后重启 API。退出按钮在后台侧栏下方。

## 管理文章

打开 [内容管理](http://127.0.0.1:3100/admin/content)。默认显示全部文章，每页 50 条，可按日文或原文标题、原文 URL、内容 ID 查询，也可组合筛选来源、公开/仅摘要/已撤稿/未公开/处理失败、精选/普通资讯。

| 操作 | 具体步骤 | 结果 |
|---|---|---|
| 修改日文标题、摘要、推荐理由 | 点击文章标题 → 人工修正 → 填写字段与修改原因 → 保存修正 | 人工值优先，后续模型重处理不会覆盖 |
| 调整分类和标签 | 人工修正 → 栏目、标签 | 标签用逗号分隔；修改会重投影公开内容 |
| 加入或移出精选 | 人工修正 → 精选 → 强制入选/强制不选 | 不修改原始模型评分；归组和公开条件仍需满足 |
| 恢复模型生成值 | 清空已有人工文字，或把分类/精选改回不修正/按模型 | 撤销对应字段的人工覆盖，不删除原始分析 |
| 下架 | 公开范围 → 下架 → 填写原因 → 应用 | 从公开出口移除，文章链接返回 404；后台保留原文和审计 |
| 恢复已下架文章 | 列表筛选已撤稿 → 文章 → 公开范围 → 公开 | 按同一公开规则恢复 |
| 收录控制 | 标记收录 / 取消收录 → 填写原因 | 控制该文章的 robots 和站点地图；预览整站 noindex 优先 |
| 重新处理 | 重新评估、重新抽取正文或重新归组 | 进入 worker 队列；重新评估会产生模型费用 |

“仅摘要”保留直接阅读的短摘要，不等于重新加入公开资讯列表；来源全文权限始终独立，不能通过改稿取得原文全文转载权。前台、RSS、API、MCP 和报表引用共同执行公开范围。页面/站点地图缓存更新可能需要几分钟，搜索引擎更新还取决于再次抓取。

本机预览关闭 worker、采集和模型调用，因此排队重处理不会自动执行。已生成内容仍可编辑。正式 worker 启动后，在 [运行](http://127.0.0.1:3100/admin/runs) 查看任务；不要清空回执以强行重试费用不明的请求。

## 信源和费用

- [信源](http://127.0.0.1:3100/admin/sources)：新建来源、预览解析、设置每小时频率、启停和查看失败。来源通过使用条件核验后才启用；保持全文展示和全文分发关闭。
- [模型](http://127.0.0.1:3100/admin/models)：查看各步骤模型，本站默认 OpenAI GPT-6 Luna。
- [设置](http://127.0.0.1:3100/admin/settings)：查看/调整应用调用预算。本站 OpenAI 每月 $8；它不是共享 Default project 的平台硬额度。
- [审计](http://127.0.0.1:3100/admin/audit)：按操作者、动作和时间检查改稿、撤稿及配置修改。

## 三个新增模块

- [模型榜管理](http://127.0.0.1:3100/admin/model-leaderboard)：查看源数据状态、排队刷新，检查待发布的集计结果并审核发布；维护带来源日期的价格、上下文与汇率。见 [榜单说明](model-leaderboard-jp.md)。
- [Codex 监控](http://127.0.0.1:3100/admin/monitor)：管理公告来源、采集/识别状态、人工复核、事件修改与撤回。免费官方来源和需要单独凭据的 X 来源分别配置；服务故障不等于额度重置。见 [监控说明](codex-monitor-jp.md)。
- [主题大事记](http://127.0.0.1:3100/admin/topic-chronicle)：维护有日期和来源的公司历史，启用或撤下；最新公开资讯自动参与主题时间线。见 [大事记说明](topic-chronicle-jp.md)。

## SEO 已实现的部分

[SEO 与上线配置](http://127.0.0.1:3100/admin/seo) 展示实际站点地址、HTTPS 配置、预览状态、可索引文章数量、联系邮箱配置、Google/Bing HTML 验证值是否存在及 IndexNow 开关。

公开页面自动生成日文标题与描述、canonical、`ja-JP`、Open Graph/X 分享卡片、JSON-LD；首页、主题、报表、文章和榜单按各自内容生成。新闻结构化数据引用原始来源，不冒用原作者身份。`/sitemap.xml` 列出可收录页面，排除未到发布时间及撤稿文章；`/robots.txt` 声明站点地图及后台限制。后台、收藏和站内搜索页不收录。

预览的 HTML 和 HTTP 响应头明确 `noindex`。这符合 [Google 的 noindex 说明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)；robots.txt 中的抓取限制本身不等同删除索引。

## 正式域名启用时

1. `.env` 设置 `SITE_URL=https://正式域名`、`SITE_DOMAIN=正式域名`，在 `site/site.ts` 填写运营联系邮箱和运营信息，并确认条款。
2. 完成受限试运行后，设置 `SITE_PREVIEW=false`、公开 Caddy 配置并重建相关服务。验证 HTTPS、首页 canonical、OG 和 sitemap 都使用同一个正式域名。
3. 在 Google Search Console / Bing Webmaster Tools 添加该站点。域名属性通常采用 DNS 验证；也支持 URL 前缀属性的 HTML 验证方式。在 `.env` 中只填写公开 `content` 值：`GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION`，不填写整段 `<meta>`，重建 Web 后在各平台点击验证。见 [Google 所有权验证说明](https://support.google.com/webmasters/answer/9008080)。
4. 在平台提交 `https://正式域名/sitemap.xml`，检查几篇真实文章和手机显示；实际收录及排名需要在平台查看。
5. IndexNow 为可选渠道；配置合法 `INDEXNOW_KEY` 后才可开启 `INDEXNOW_SUBMIT_ENABLED`。它不替代 Google Search Console，也不保证收录。

当前没有正式域名的 DNS、TLS 和搜索引擎所有权验收记录。后台显示“验证值已配置”仅指本地配置，绝不表示已完成平台验证。
